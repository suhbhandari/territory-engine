## Goals with nothing built

| Item | What it needs |
|---|---|
| Weekly refresh | A `make refresh` that re-runs enrich for the current list, re-scores, rewrites only out-of-date briefs and sequences, and rebuilds the public copy. Two completed runs a week apart are the target before shipping. |
| Trigger list | A diff between two refreshes: accounts whose tier changed, whose open roles moved between ranges, or whose careers page appeared or disappeared, with the date each signal was collected. Needs the refresh first. |
| Monday playbook | A one-page doc for a rep: open the trigger list, work tier A groups by rank, read the brief, adapt and send the drafts, log the outcome. |
| Impact write-up | A timed study: for 5 sample accounts, minutes to research and draft by hand versus with the engine, then weekly hours saved per rep with the arithmetic shown. Until then, no time-saved claim. |
| Closing the loop | How outcome data (replies, meetings, opportunities) is recorded against `Territory Engine ID` and used to re-weight `rubric.yaml`. Needs outcome data to exist. |
| Second metro test | Run the runbook end to end for a second metro, by someone other than the author, and count the doc fixes needed. Needs item 16 below, or the manual file moves the runbook describes. |
| Second vertical (Phase 9) | Add a second `config/verticals/<name>/` and record which core files had to change. Needs item 15 below. |
| Contacts | A route from account to named person (a licensed contact database or an enrichment table fed from the Outreach export). |
| Evals with people | Hand-grade a sample of briefs and drafts; add an LLM judge; measure judge versus hand-grade agreement. |
| Prompt versions | Log a prompt version (or hash) and first-pass check failures per item in the brief and sequence indexes, so failure types can be counted per prompt version. Today only the final pass is kept. |
